# 大鹅的奇怪暑假：Web + AI MVP 设计

日期：2026-10-05。状态：文档初稿，等待审阅；本文件描述目标行为，不代表已实现。

## 1. 产品目标与边界

玩家扮演一只卡通大鹅，在七天暑假中选择活动，把兴趣卡组合成纪念物，最后得到一页手账和一封写给自己的信。一局目标时长约 3 分钟，实际以试玩为准。

个人特色通过好奇、动手、运动、记录和多样生活表达，使用原创虚构文案。手账展示选择留下的痕迹，不对玩家进行人格诊断，不把选择评价成自律或懒惰。

MVP 是独立浏览器游戏，支持桌面与手机。包括完整玩法、本地续玩、AI 纪念物故事、AI 结尾信、手账 PNG 导出。暂不加入登录、数据库、联机、排行榜、付费、钱包、NFT、语音、自由聊天、实时生图或知识库检索。

## 2. 核心规则

一局 7 天，每天上午、下午各 1 次选牌，共 14 次。六种活动卡：学习、制作、运动、散步、记录、分享。

每次展示三张候选卡：从六种类型中等概率抽取三个不同类型。玩家选择一张，其他两张放弃。合成不消耗时间；开始下一次选牌前可以查看配方并合成。

手牌上限 6 张。若选择新牌时手牌已满，进入替换阶段：保留已选新牌，点击一张旧牌弃掉，再把新牌加入并推进一次时间。替换完成前暂停其他选牌与合成，禁止手牌超限和重复推进。提供“取消替换”返回同一组候选牌，不消耗时间。

### 配方

| ID | 消耗卡片 | 纪念物基础名 | 愿望类别 |
| --- | --- | --- | --- |
| tool | 学习 × 2、制作 × 1 | 自己做的小工具 | 作品 |
| training | 运动 × 2、记录 × 1 | 一页训练新纪录 | 身体 |
| essay | 散步 × 1、记录 × 1、分享 × 1 | 一篇有感受的短文 | 生活 |
| demo | 学习 × 1、制作 × 1、分享 × 1 | 第一个小游戏 Demo | 作品 |
| evening | 运动 × 1、散步 × 1、记录 × 1 | 操场晚风明信片 | 生活 |

每次合成原子检查并消耗三张卡，生成唯一纪念物实例。允许重复获得同一配方的纪念物。所有配方一开始可查阅，显示已持有/所需数量，缺卡时禁用合成。

每局固定三个愿望：留下一件作品、一份身体记录、一段生活记忆。首次获得对应类别纪念物就盖章，重复不增加愿望数。首版不随机目标，减少规则和调试复杂度。

第 14 次选牌后进入最后整理阶段：不再发牌，允许继续合成，明确显示“结束暑假”。点击才结算；没有纪念物也能结束。结算不产生新卡或新纪念物。

“再过一个暑假”重置局 ID、回合、候选、手牌、待替换卡、愿望、纪念物、事件和 AI 请求状态。

## 3. 状态与存档

状态流：规则说明 → 选牌 ↔ 满手替换 → 最后整理 → 结算 → 新一局。配方面板是覆盖层，不改变时间。

规则模块采用纯函数或 reducer；界面发出固定动作 PICK_CARD、REPLACE_CARD、CANCEL_REPLACE、CRAFT、FINISH、RESTART。AI 响应只能更新文字字段，不能触发规则动作。

最小存档字段：schemaVersion、runId、turn（0–14，表示已完成选牌次数）、phase、candidates、hand（独立实例 ID 与类型）、pendingCard、souvenirs、events、ending。愿望完成情况从纪念物类别推导，避免重复存储不一致。

每次合法状态变化保存到 localStorage 的 summer.save.v1。候选卡和待替换卡必须保存，刷新不能重抽当前选项。存档加载时校验版本、类型、实例 ID 唯一性、手牌数量和状态一致性；损坏时提示开启新局，不能静默卡死。存储不可用时降级为本次页面内游玩。

AI 的 pending 请求不序列化为可恢复任务。刷新后未完成生成的内容使用模板；可以手动发起一次新请求。纪念物和结算始终先保存游戏事实，再发 AI 请求。

## 4. AI 加持与费用控制

AI 用于两项：合成后赋予纪念物独特名字和 1–2 句小故事；结算时依据本局选择、合成、弃牌生成标题与一封短笺。

纪念物生成不阻塞游戏：先展示基础名和模板，AI 就绪后更新文字。结束时立即显示手账，信件可稍后完成；导出不等待模型。

### 服务端接口契约

POST /api/ai/souvenir 输入 runId、souvenirId、recipeId、craftedAtTurn、截至合成时的活动计数；输出 source（ai/template）、title（1–20 中文字符）、story（1–100 中文字符）。

POST /api/ai/ending 输入 runId、14 回合以内的固定类型事件、纪念物的 ID/recipeId/类别；输出 source、title（1–24 中文字符）、letter（1–240 中文字符）。结尾依据游戏事实生成，不信任客户端传来的自然语言故事作为事实。

服务端对类型、长度、事件数量与配方 ID 做白名单校验。模型输出为固定 JSON，校验失败、网络错误、超时和未配置密钥时返回事实一致的模板。标题更名与文本渲染不使用 HTML，不让模型内容变成可执行脚本。

基础名、配方、类别和发生回合由程序保留。文案不声称发生了额外活动、获得额外道具或完成缺失愿望。无法可靠校验的自由文本优先回退为模板。

每次合成最多 1 个模型请求；14 张卡最多合成 4 个纪念物，加结尾 1 个，一局正常路径最多 5 次。超时设为 10 秒，无自动重试。请求以 runId + kind + objectId 去重；并发上限 1，其余入队。结算取消未开始的纪念物任务，优先生成结尾。

重开时取消或忽略旧局全部请求，响应必须匹配当前 runId。结算模板提供一次手动“重新写信”，成功后禁用；重试单独计入预算。

本地浏览器去重只减少误触成本，不构成公共服务的计费安全边界。公共部署前必须加服务端持久限流、幂等缓存与每日费用上限；单进程内存计数只适合本地开发。只记录请求类型、耗时、状态和用量，不打印密钥或完整提示词。

首版服务端适配 OpenAI 兼容接口，使用 AI_PROVIDER_BASE_URL、AI_PROVIDER_API_KEY、AI_PROVIDER_MODEL，均非 NEXT_PUBLIC 环境变量。模型与提供方在接入时确认；缺失配置时明确为模板模式。Maker 制作积分是否能用于这个接口，当前未获验证，不作为运行前提。

## 5. 界面与视觉

暖米白、草绿、橙色；原创 Q 版大鹅用 SVG，书桌、卡片和纪念物使用轻量 DOM/CSS/SVG。

桌面：左侧桌面与纪念物，右侧候选牌、手牌和配方。手机：顶部天数与愿望，中部简化书桌，下部选牌和手牌，配方为可关闭面板。允许页面纵向滚动，不以压缩字号追求强制一屏。

三选一卡显示活动名和原创短句。六张手牌用网格，重复卡也能独立选择。盖章、合成、弃牌均有即时反馈；动画不参与计时判定。触控区域至少约 44px，支持键盘操作、明显焦点、关闭规则、减少动态效果。

结算展示纪念物实例、3 类愿望完成情况和信件。PNG 手账由本地绘制生成，使用已得到的文本与本地 SVG 资源，不把截图上传给模型，不实现公共分享链接。

## 6. 模块与技术方案

拟采用 Next.js + React + TypeScript，具体版本在实现时检查官方文档并锁定。前端无需 Canvas 游戏循环或物理引擎；PNG 导出可以使用独立 Canvas 绘制工具。

| 模块 | 责任 | 依赖 |
| --- | --- | --- |
| game/rules、recipes、types | 固定玩法、合法动作、配方与事件 | 不依赖 React 或网络 |
| game/save | 存档版本、校验与恢复 | 浏览器存储适配器 |
| components/game | 卡片、手牌、配方、桌面与愿望 | 规则状态与动作 |
| components/ending | 手账、信件、重开与导出 | 结算数据 |
| lib/api | 请求队列、取消和旧响应过滤 | 服务端 API |
| app/api/ai | 输入校验、预算、模型调用、输出与回退 | 服务端 provider 配置 |
| lib/export | 本地手账 PNG | 已完成局的数据 |

首版不建数据库。公开 AI 服务的持久限流需求可以通过部署平台能力解决，平台尚未选择；未满足费用约束前只开放模板玩法。

## 7. MVP 验收

规则测试：14 次选择精确推进；候选每组 3 种不同类型；满手替换和取消正确；重复卡精确消耗；无卡合成不改变状态；盖章去重；末回合仍可合成；重开完整重置。

真实浏览器：至少完整玩两局，其中一局触发满手弃牌、一局拿到全部三类愿望；若自然随机难覆盖，使用开发测试种子，并明确标记测试模式。不得为了截图宣称随机平衡已通过。

浏览器分别检查 390×844 手机竖屏与 1440×900 桌面；候选、手牌、配方、结算无横向溢出和遮挡，按钮可触控，刷新可恢复当前候选与满手替换状态。

AI 验证：真实提供方生成至少一个纪念物与一封结尾信；模拟超时、错误 JSON、网络失败、缺密钥、限流时仍能结算；重开后旧响应无污染；保存或导出不能额外发起模型调用。

交付证据：可运行的本地地址、关键截图、规则测试/lint/build 结果、真实 AI 通过或受控阻塞说明。游戏可玩 MVP 与真实 AI 接入分别报告。

## 8. 开放决策

普通 Web 是当前工作假设；若要区块链 Web3，在写代码前重新确认。AI 提供方、密钥来源、公共部署平台与费用上限在 M2 接入前确定，均不阻塞 M1 的可玩闭环。
