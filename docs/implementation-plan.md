# 开发顺序与完成标准

日期：2026-10-05。状态：实施阶段草案；当前仅初始化文档，尚未启动各里程碑。

## 依赖图

M0 文档确认 → M1 可玩闭环 → M2 真实 AI → M3 界面、导出与完整验收。

不启动并行 Agent。美术调整可以在规则接口稳定后与 AI 接入交错推进，但不得同时修改游戏状态协议。

## M0：文档与仓库

产物：README、AGENTS、MVP 设计、开发顺序、Maker 积分调查、独立 Git 仓库。用户审阅后开始代码实现。

普通 Web 与区块链需求若有歧义，按设计文件中的范围处理，不擅自加入链上系统。

## M1：完整可玩的网页

前置：玩法与普通 Web 范围认可。

顺序：核验并锁定框架版本 → 创建最小项目 → 实现固定配方和 reducer → 规则测试 → 桌面/手机界面 → 存档恢复 → 模板结算。

完成：不需要模型密钥，能够走完 14 次选牌、满手替换、合成、末回合整理、结算和重开。保存本地运行地址、测试结果与真实浏览器截图。

## M2：AI 纪念物与结尾信

前置：M1 通过；合法模型 API 提供方、服务端密钥、调用预算可用。Maker 网页额度不能代替 API 验证。

顺序：服务端 provider 适配与环境变量示例 → 输入/输出校验 → 纪念物请求 → 结尾请求 → 队列、取消、幂等与费用控制 → 回退路径验证。

完成：至少一次真实纪念物和一次真实结尾信生成成功；缺密钥、超时、错误响应、限流可回退；新局不被旧局响应污染。只有模板时标记“AI 接入受控阻塞”，不能宣称真实 AI 完成。

## M3：交付验收

前置：M1 通过；M2 真实通过或明确记录受控阻塞。

顺序：手账 PNG 导出 → 视觉和触控反馈 → 手机/桌面两尺寸检查 → 完整两局试玩 → lint/build → 截图和交付说明。

公共部署前额外确认服务端持久限流、幂等缓存、每日费用预算；否则仅部署模板模式。部署平台选择和上线操作另行安排。

## 粗略时间

熟悉 Web 工具链的前提下，M1 约 0.5–1 天，M2 约 0.5–1 天，M3 约 0.5–1 天。合计约 2–3 天，属于范围估算，受模型接口与真实试玩问题影响。

## 验收记录格式

每个里程碑记录版本、操作、预期、实测、证据与阻塞。区分单测通过、构建成功、真实可玩、真实模型成功。当前这些结果均未产生。
