**目标：** 让玩家陪大鹅阿满度过七天，在蝉鸣湾办成「夏天来过的小证据」小展览，并交付符合赛事要求的网页小游戏。

**架构：** React 静态前端通过纯 reducer 执行固定规则，用 localStorage 本地续玩；运行时 AI 由独立 Qoder Edge Function 提供，浏览器同源调用。角色与道具在制作期用 AI 生成，随应用静态发布，不依赖玩家实时生图。

**已确认技术栈：** React + TypeScript + Vite、Tailwind CSS + shadcn/ui、纯 reducer、localStorage、Canvas 2D、Vitest + Playwright。公开站点是 Vercel 静态前端；运行时 AI 仍按 Qoder Edge 与服务端原生 fetch 设计，尚未实现。不引入 Next.js 服务端或游戏引擎。版本已锁定，见下方 M1 记录。包管理遵循设计第 6.1 节，锁文件为 bun.lock。

**设计依据：** [MVP 设计](mvp-design.md)、[赛事要求](1024-coding-weekend-game-track.md)、[项目协作约定](../AGENTS.md)。

## 全局约束

- 一局 7 天、每天上午下午各一次，共 14 次三选一；布袋手牌上限 6 张，合成消耗 3 张、不耗时间，最多 4 件展品。
- 六种活动展示名固定为研究、捣鼓、扑腾、溜达、记录、分享；五个配方及三类展签以设计第 2 节为唯一依据。
- 三类展签为小小创造、身体出过门、日子有回声；同类重复不增加愿望数，未集齐或零展品也能开张与重开。
- 第 14 次选牌完成后仍可合成，玩家点击「小展览开张」才结算；满手替换未完成时不能越过该阶段。
- 暖心、具体、不说教；不加金币、经营、体力、跑图、天气增益、惩罚或跨局解锁，不为展品另做小游戏。
- 固定规则与存档不能依赖 AI；前端不能持有密钥；不读取或上传私人资料和其他项目凭据。
- 制作期 AI 角色与道具是赛事硬要求，运行时 AI 文案不可用不免除这项要求。
- 完整 MVP 包含 PNG 导出与真实运行时 AI 验证；赛事最低交付与完整 MVP 分开报告，不能把未做功能标成完成。
- 实现后依次执行规则测试、lint、build、真实浏览器试玩；纯文档更新不新增或运行应用测试。
- 2026-10-25 15:00 封板停止开发，16:00 作品提交截止；OpenDev 活动额度在 19:00 回收。

## 依赖与优先级

主路径为 M0 文档确认 → M1 可玩闭环与 AI 美术 → M3 赛事交付。M2 在 M1 通过后接入，成功或受控阻塞均可进入 M3，不让模型密钥与额度阻塞游戏交付。

M1 通过后先准备 M3 的可玩链接和主角卡，再在封板前安排 M2、PNG 导出和最终回归。美术调整可以在规则接口稳定后与 AI 接入交错推进，但不同时修改游戏状态协议。

公开运行时 AI 还依赖合法模型 API、服务端密钥、持久限流、幂等缓存和每日费用上限。无法满足时只发布明确标识的模板玩法。2026-10-24 已授权并发布的是 Vercel 静态模板站；新建站点、后端资源和更换平台仍须单独授权。

## 责任边界与拟落点

前端模块已在 src 落地，构建产物在 dist。结算画面是 src/components/game/EndingScreen.tsx。functions、src/lib/api、src/lib/export 仍未创建。目录边界以设计第 6 节为准。

| 模块 | 职责 | 对外约束 |
| --- | --- | --- |
| src/game/types、rules、recipes | 状态、固定动作、六类活动、五个配方、三类展签 | 不依赖 React、浏览器或模型；合成与替换原子处理 |
| src/game/save | 本地持久化、版本与状态校验 | 保存候选、待替换卡、台词、满手已提示标记和材料提醒；不恢复 AI pending 任务 |
| src/components/game | 阿满、展桌、候选、布袋、配方与提示 | 只发规则动作，不自行修改卡片或回合 |
| src/components/ending | 三种结算分支、短笺、重玩提示 | 不新增展品，提示只依据本局配方记录 |
| src/components/ui | shadcn/ui 基础交互组件 | 复用可访问行为，以 Tailwind 主题形成游戏外观 |
| src/lib/api | 前端请求队列、取消、去重与旧响应过滤 | 同源调用 /functions/v1/app，不能持有服务密钥 |
| functions/index.ts | Qoder Edge 入口与服务端配置读取 | 函数依赖自包含，不运行 Node 常驻服务 |
| functions/handler.ts、functions/ai | action 校验、费用控制、模型调用与模板回退 | 基于 Web Request/Response 和 fetch；AI 只能更新文字 |
| src/lib/export | 本地 Canvas 2D 手账 PNG | 使用已保存的本局数据和本地图片，不调用模型 |
| 静态美术与交付材料 | 阿满、五种展品、主角卡 | 可追溯到 AI 生成结果，卡中使用真实游戏画面 |

Vitest 覆盖规则、存档和可独立执行的函数处理逻辑，Playwright 覆盖真实浏览器操作；Deno 入口兼容性和实际部署请求单独验证。只在确需 Vercel 备用部署时增加该平台的函数入口，不预先实现两套服务端。
